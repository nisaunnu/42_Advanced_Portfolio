## Kavramlar

### "Paket" (package) nedir?
Normalde bir Python dosyası yazıp `python dosya.py` ile çalıştırırsınız. Ama bazen
yazdığınız kodu **başka insanların da kendi projelerinde `import` ile kullanmasını**
istersiniz. İşte bu şekilde dağıtılabilen, kurulabilen koda **paket** denir.

Örnek: `numpy`, `pandas` de birer pakettir. Siz `pip install numpy` yazarsınız,
sonra `import numpy` ile kullanırsınız. Ex09'da tam olarak bunu, ama kendi minik
paketimiz için yapacağız: `ft_package` adında bir paket.

### `pip` nedir?
`pip`, Python'ın paket kurma/kaldırma aracıdır. `pip install X` dediğinizde, X paketini
bilgisayarınıza kurar; böylece herhangi bir `.py` dosyasından `import X` yazabilirsiniz.

### `pyproject.toml` nedir?
Bir paket oluşturmak istediğinizde, pip'e "bu paketin adı ne, versiyonu ne, hangi
dosyaları içeriyor" gibi bilgileri bir yerde yazmanız gerekir. İşte bu bilgi dosyasına
`pyproject.toml` denir. Kısaca: **paketin kimlik kartı.**

### `build` aracı nedir?
`pyproject.toml` + kaynak kodunuzdan, gerçekten kurulabilir iki dosya üretmeniz gerekir:
- `.tar.gz` (kaynak kod arşivi)
- `.whl` (önceden derlenmiş, hızlı kurulan format — "wheel" / tekerlek diye geçer)

Bu üretim işini yapan araca **`build`** denir. Kendisi bir Python paketidir, bu yüzden
önce onu kurmanız gerekir.

```bash
pip install build
```

Bu kurulum bittikten sonra `python -m build` komutu çalışacaktır.

> **Not:** Eğer conda ortamınızda (`python_env`) hâlâ hata alırsanız, o ortamın aktif
> olduğundan emin olun (`conda activate python_env`) ve tekrar `pip install build`
> deneyin. Bazı sistemlerde `pip` yerine `python -m pip install build` yazmak daha
> güvenlidir çünkü bu, "hangi Python'ın pip'i kullanılıyorsa ona kur" anlamına gelir.

## Klasör yapısını anlayalım

Şu an `ex09/` klasörünüzde şunlar olmalı:

```
ex09/
├── ft_package/
│   └── __init__.py        ← paketin gerçek kodu burada
├── pyproject.toml         ← paketin kimlik kartı
├── README.md              ← paket açıklaması
├── LICENSE                ← lisans metni
└── requirements.txt       ← bağımlılık listesi (bizde boş, çünkü dışarıdan
                              hiçbir kütüphaneye ihtiyacımız yok)
```

### Neden `ft_package` adında bir **klasör** var, tek bir `.py` dosyası değil?

Çünkü Python'da "paket" = **içinde `__init__.py` olan klasör** demektir. Bu dosya,
klasör `import` edildiğinde ilk çalışan dosyadır. Siz:

```python
from ft_package import count_in_list
```

yazdığınızda, Python şunu yapar:
1. `ft_package` adında bir klasör/paket arar.
2. Onun `__init__.py` dosyasını çalıştırır.
3. İçinde `count_in_list` adında bir şey var mı diye bakar, varsa onu size verir.

Bu yüzden **klasör adı ile import ettiğiniz isim birebir aynı olmak zorunda.**

## `ft_package/__init__.py`

```python
"""ft_package: a sample test package.

This package exposes a single utility function, count_in_list,
which counts how many times a given element appears in a list.
"""

__version__ = "0.0.1"


def count_in_list(lst: list, element: any) -> int:
    """Count the number of occurrences of element in lst.

    Args:
        lst (list): the list to search into.
        element (any): the element to count.

    Returns:
        int: the number of times element appears in lst.
    """
    return lst.count(element)


__all__ = ["count_in_list"]
```

### Satır satır ne oluyor?

- **En üstteki `"""..."""` bloğu** → dosyanın (modülün) dokümantasyonu (`__doc__`).
  Piscine kuralı "her fonksiyonun dokümantasyonu olmalı" diyor, bu da modül seviyesinde
  aynı mantığı uyguluyor.

- **`__version__ = "0.0.1"`** → paketin versiyon numarasını tutan bir **sabit**
  (constant), fonksiyon değil. Bu bir "global değişken" değildir çünkü:
  - Hiçbir fonksiyon onu okumuyor veya değiştirmiyor.
  - Sadece dışarıdan `pip show` gibi araçların okuması için orada duruyor.
  - Bu, tüm Python paketlerinde (numpy, pandas dahil) kullanılan standart bir
    konvansiyondur.

  **Eğer siz yine de hiç risk almak istemiyorsanız**, bu satırı tamamen silebilirsiniz;
  hiçbir işlevi bozmaz, sadece `pip show` çıktısında versiyon bilgisini `pyproject.toml`
  dosyasından okur (zaten oradan da tanımlı).

- **`def count_in_list(lst: list, element: any) -> int:`** → asıl fonksiyonumuz.
  `lst.count(element)`, Python'ın listeler için hazır sunduğu `.count()` metodunu
  kullanarak elemanın kaç kez geçtiğini sayar.

- **`__all__ = ["count_in_list"]`** → "Biri `from ft_package import *` yaparsa,
  sadece `count_in_list`'i dışarı ver" demek. Bu da bir sabit, mantık içermiyor.
  İsterseniz bunu da silebilirsiniz, zorunlu değildir.

### Global değişken yasağı burada nasıl uygulanıyor?
Fonksiyonun içine bakın: `count_in_list` **hiçbir dış değişkene dokunmuyor.**
Aldığı parametrelerle (`lst`, `element`) işini yapıp sonucu `return` ediyor. Yani
fonksiyon tamamen bağımsız (bu konsepte "pure function" denir) — piscine'nin istediği
tam olarak bu.

## `pyproject.toml` — paketin kimlik kartı

```toml
[build-system]
requires = ["setuptools>=68.0"]
build-backend = "setuptools.build_meta"

[project]
name = "ft_package"
version = "0.0.1"
description = "A sample test package"
readme = "README.md"
requires-python = ">=3.10"
license = { text = "MIT" }
authors = [
    { name = "eagle", email = "eagle@42.fr" }
]

[project.urls]
Homepage = "https://github.com/eagle/ft_package"

[tool.setuptools]
packages = ["ft_package"]
```

### Bölüm bölüm açıklama:

- **`[build-system]`** → "Bu paketi derlerken hangi aracı kullan?" cevabı: `setuptools`.
  Bu bölüm olmadan `pip`/`build`, paketinizi nasıl paketleyeceğini bilemez.

- **`[project]`** → paketin künyesi. Buradaki her satır, sizin `pip show -v ft_package`
  komutunda gördüğünüz alanlara karşılık geliyor:

  | pyproject.toml | `pip show -v` çıktısı |
  |---|---|
  | `name` | `Name:` |
  | `version` | `Version:` |
  | `description` | `Summary:` |
  | `authors` | `Author-email:` |
  | `license` | `License:` |

- **`requires-python = ">=3.10"`** → piscine kuralı "Python 3.10 kullanmalısınız"
  diyordu, bu satır bunu paket seviyesinde de garanti altına alıyor: biri sizin
  paketinizi Python 3.9 ile kurmaya çalışırsa hata alır.

- **`[tool.setuptools] packages = ["ft_package"]`** → "Hangi klasörü pakete dahil et?"
  cevabı. Bunu unutursanız bazı setuptools sürümleri paketinizi bulamaz.

## `README.md` ve `LICENSE`

- **`README.md`**: Paketinizin ne işe yaradığını, nasıl kurulup kullanılacağını
  anlatan tanıtım dosyası. PyPI'ye paket yüklerseniz, PyPI sayfasında bu metin görünür.

- **`LICENSE`**: Kodunuzu kimlerin, nasıl kullanabileceğini belirten hukuki metin.
  Biz MIT lisansını seçtik (en yaygın, en izin verici lisanslardan biri — "kaynağı
  belirtirsen istediğini yap" der).

## Şimdi terminalde adım adım ne yapacaksınız

Terminalinizi açın, `ex09` klasörünün içine gidin (`cd` ile), ve **sırayla** şu
komutları çalıştırın. Her komuttan sonra ne olduğunu okuyun.

### Adım 1 — `build` aracını kurun (bir kere yapılır)
```bash
pip install build
```
Bu, "paket üretme" işini yapacak aracı indirir.

### Adım 2 — Paketinizi derleyin
```bash
python -m build
```
Bu komut çalışınca, `ex09/` içinde yeni bir `dist/` klasörü oluşur, içinde:
```
dist/ft_package-0.0.1.tar.gz
dist/ft_package-0.0.1-py3-none-any.whl
```
İki dosya belirir. Bunlar sizin "gerçek", kurulabilir paketinizdir.

### Adım 3 — Paketinizi kendi bilgisayarınıza kurun
```bash
pip install ./dist/ft_package-0.0.1-py3-none-any.whl
```
Bu komut, tıpkı `pip install numpy` yazar gibi, kendi paketinizi sisteminize kurar.

> Eğer daha önce kurduysanız ve tekrar denemek isterseniz:
> ```bash
> pip install ./dist/ft_package-0.0.1-py3-none-any.whl --force-reinstall
> ```

### Adım 4 — Kurulumu doğrulayın
```bash
pip show -v ft_package
```
Çıktıda `Name: ft_package`, `Version: 0.0.1` gibi bilgileri göreceksiniz — PDF'deki
örnekle neredeyse birebir aynı.

```bash
pip list
```
Bu komutu çalıştırdığınızda listede `ft_package` satırını göreceksiniz.

### Adım 5 — Paketi gerçekten kullanın
Herhangi bir yerde (ex09 klasörünün dışında bile) yeni bir Python dosyası açıp
şunu yazın ve çalıştırın:

```python
from ft_package import count_in_list

print(count_in_list(["toto", "tata", "toto"], "toto"))  # 2
print(count_in_list(["toto", "tata", "toto"], "tutu"))   # 0
```

Eğer `2` ve `0` yazdırıyorsa, **paketiniz tam anlamıyla çalışıyor demektir.**

## Sık karşılaşılan hatalar

| Hata                                            | Sebebi                                                                            | Çözüm               |
|-------------------------------------------------|-----------------------------------------------------------------------------------|---------------------|
| `No module named build`                         | `build` paketi kurulu değil                                                       | `pip install build` |
| `No module named ft_package`                    | Paket henüz kurulmadı                                                             | Adım 3'ü çalıştırın |
| `error: Multiple top-level packages discovered` | `[tool.setuptools] packages = [...]` satırı eksik/yanlış                          | `pyproject.toml`'da bu satırın olduğundan emin olun |
| Kurulum sonrası eski kod çalışıyor gibi         | pip eski sürümü cache'lemiş olabilir                                              | `pip install ... --force-reinstall --no-cache-dir` |
| `externally-managed-environment` hatası         | Sisteminiz pip'in doğrudan kurulum yapmasını kısıtlıyor (Debian/Ubuntu'da yaygın) | conda ortamınızdaysanız bu hatayı almamalısınız; alıyorsanız `conda activate python_env` yapıp tekrar deneyin |

## Git'e ne göndereceksiniz?

Turn-in listesi: `*.py, *.txt, *.toml, README.md, LICENSE`

Yani şu 5 dosyayı `ex09/` klasörünüze koyup commit edin:
```
ex09/ft_package/__init__.py
ex09/pyproject.toml
ex09/requirements.txt
ex09/README.md
ex09/LICENSE
```

**`dist/` klasörünü ve `ft_package.egg-info/` klasörünü commit etmenize gerek yok** —
bunlar `python -m build` komutuyla her an yeniden üretilebilen, otomatik oluşan
dosyalardır. Değerlendirici zaten sizin `pyproject.toml`'unuzdan kendi `dist/` klasörünü üretip test edecektir.
